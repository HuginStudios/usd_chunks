    usd_chunks.chunk_notice

    Notices and the dependency graph behind every chunk object.

    Tf.Notice is USD's built-in callback system, similar to Qt's signals. This module uses Tf.Notice extensively but hides most of its API, so a client can be up and running with callbacks without managing the lifetime of listeners.

    ChunkNoticeAlias names each supported notice class, so the notice you are interested in can be found without caring how it is implemented. Every custom notice subclasses ChunkNotice, which carries additional data whose type depends on the notice and on who sends it.

    The easiest way to send a notice is explicitly, with send_notice:

    send_notice(ChunkNoticeAlias.PARAM_CHANGED, some_param, {"any": "data"})

    ChunkNoticePropagator ⚓︎

    ChunkNoticePropagator(*args, **kwargs)

    Base class that makes chunk objects connectable, to each other and to callbacks.

    Chunk objects connect to each other through 'physical' connections and to callbacks through 'non-physical' ones. Physical connections rely on dependencies (inputs) and dependants (outputs and owners); non-physical connections rely on the Tf.Notice system and have no dependencies. Callbacks are non-physical; inputs, outputs and the owner are physical.

    Physical:

    'Children' reference their owning object (parent), and call data_changed() on the owner when the child has been modified. The DagNode manages these connections: it holds references to inputs, outputs and an owner, and solves its outputs recursively while respecting dependencies, so a node does not solve until all its inputs are solved. Any number of dependencies (inputs) can be added to an instance of this class; once all of them are solved, the instance's DagNode solves too, calling data_changed(). Combined with callbacks, this lets a client build dependency graphs of chunk classes and have the system trigger callbacks when appropriate.

    Non-physical:

    Connections added with add_callback are not managed by the DAG. The Tf.Notice system manages them, without any dependency information, so a callback never triggers another callback implicitly.

    By default send_self() is called whenever an attribute or child attribute has been modified. The notice sent is decided by get_notice_alias(), and the DagNode also propagates it up the owner hierarchy.

    get_edit_context(), get_layer_identifier() and get_stage() can be implemented to support layer contexts when modifying the stage. A NoticeConnection sets the edit context to the layer returned by get_edit_context() before running its callback, which keeps callbacks contained to the layers managed by ChunkLayerManager. See NoticeConnection.handle_callback.

    def add_callback(
    self,
    method: Callable[[NoticeT, Any], Any] | Callable[[Self, NoticeT, Any], Any],
    sender: ChunkNoticePropagator | None = None,
    listen_globally: bool = False,
    notice_alias: ChunkNoticeAlias = ChunkNoticeAlias.NONE,
    send_on_create=False,
    private=False,
):
    """Subscribe a callback to a notice.

    When the notice is sent, `method` is called with one of two signatures, chosen from the
    callback's own declared parameters:

    (notice(Tf.Notice), sender(Any))
        Matches Tf.Notice. This is what a bound method gets, where `self` is already the
        object holding the state -- the preferred form. Plain functions may declare it too.

    (owner(Any), notice(Tf.Notice), sender(Any))
        The convenience form for module-level functions, where `owner` is the object
        add_callback was called on. Note `owner` is not the same as `sender`: `sender` is
        whatever dispatched the notice, which may be a proxy, an attribute sender, or an
        unrelated object when listening globally.

    With no sender, self is assumed to be the sender, which keeps the simple case simple::

        my_param.add_callback(my_callback)

    Args:
        method (Callable): The method to call when the notice is sent
        sender (Any, optional): The sender to subscribe to. If None, self is used unless
            listen_globally is True. Defaults to None.
        listen_globally (bool, optional): Subscribe to every notice of type notice_alias,
            whatever its sender. Defaults to False.
        notice_alias (ChunkNoticeAlias, optional): The notice to subscribe to. NONE uses the
            sender's get_notice_alias(). Defaults to ChunkNoticeAlias.NONE.
        send_on_create (bool): Also call it when the owning object is added to the scene.
            Defaults to False.
        private (bool): Keep the callback out of serialization and copies, which is what a
            callback added inside __init__ needs. Defaults to False.

    Raises:
        ValueError: It would hear another chunk. Chunks speak to each other only through
            wires: listen_globally is for the stage and the host (SCENE_ALIASES), and a
            sender is this object's own chunk or something in it.
    """
    if listen_globally and notice_alias not in SCENE_ALIASES:
        raise ValueError(
            f"listen_globally hears every chunk's {notice_alias.name}; a chunk may listen "
            f"globally only to the stage and the host ({', '.join(sorted(a.name for a in SCENE_ALIASES))}). "
            "To react to another chunk, wire it in."
        )
    if sender is not None and (mine := _chunk_of(self)) is not None \
            and (theirs := _chunk_of(sender)) is not None and theirs is not mine:
        raise ValueError(
            f"{getattr(self, 'name', self)} listens to {getattr(sender, 'name', sender)} of "
            f"another chunk ({getattr(theirs, 'name', theirs)}): to react to another chunk, "
            "wire it in -- an exec input, or an @Node.param@ expression."
        )
    # If sender is not set and we should not listen for global notices, the sender will be self
    if sender is None and not listen_globally:
        sender = self

    # If sender is specified, only subscribe to changes from it.
    if isinstance(sender, ChunkNoticePropagator) and notice_alias is ChunkNoticeAlias.NONE:
        notice_alias = sender.get_notice_alias()

    self._callbacks.add(
        NoticeConnection(method, notice_alias, sender, listen_globally, self), send_on_create, private
    )

    def add_dependency(self, input: ChunkNoticePropagator) -> int:

    execute()

    Re-execute this object, and everything downstream of it, now.

    Dirties it and solves downstream: each solved object's data_changed() runs, and with it send_self(), which triggers any connected callbacks. When the solve has finished, every chunk it reached runs its module's execute(node) once, upstream first (chunk_cook.flush, then chunk_cook.cook). Inside batched_solve() it only dirties, and the solve waits for the block to end; inside another chunk's cook, the chunks it reaches cook once that cook has ended.

    This is the one way to run a chunk again: a module's execute(node) is written, never called directly, and chunk_cook.cook is the framework's step, not an API.

    def handle_callback(self, notice, sender=None, context=True, origin=None):
    """Forward a notice to the callback, if the method, sender and owner are still alive.

    If the owner is valid and implements get_stage() and get_edit_context(), the method is
    called inside that edit context, so its stage edits land in the right layer.

    The callback may declare either (notice, sender) -- matching Tf.Notice -- or
    (owner, notice, sender). Which one it gets is decided by its own signature, so both
    forms work whether the callback is a plain function or a bound method.

    Args:
        notice (Tf.Notice): The notice to forward
        sender (ChunkNoticePropagator, optional): The sender of the original notice. Defaults to None.
        context (bool, optional): Run inside the owner's edit context. Defaults to True.
        origin (_NoticeOrigin, optional): Where the notice came from, when the caller has
            already worked it out for several listeners. Defaults to working it out.
    """
    if not (meth := self.get_method()):
        return

    owner = self.owner
    if self._owner is not None and owner is None:
        # This connection was registered with an owner and that owner has since been
        # collected, so the subscriber no longer exists. Dispatching now would hand the
        # callback a dead owner; the connection is torn down via _connection_broke.
        return

    args = (owner, notice, sender) if self._wants_owner(meth) else (notice, sender)
    if owner:
        if origin is None:
            origin = _NoticeOrigin(notice)
        cooking = _executing_chunk
        if cooking is None or getattr(owner, "get_chunk", lambda: None)() is not cooking:
            # Another chunk is cooking, and its stage is the cook's (skip_cook): only what
            # that cook reads, and whatever is looked up there is charged to it. A Set
            # Camera refreshing its menu by a Traverse during an Add Variants cook made Add
            # Variants read the whole stage, so it cooked on every edit above it. The cook
            # stage's notice is a copy -- the scene's stage hears the same layer edit -- so
            # it is dropped, and the scene's is handled on the scene's stage. With no
            # chunk cooking, a cook stage is being opened: muting its hidden layers is
            # nobody's change, and every Set Camera and Set Variant rebuilt its menus
            # for it on every masked cook.
            if origin.cook:
                return
            if cooking is not None:
                with chunk_cook.outside_cook():
                    self._call_for_owner(owner, meth, args, origin, context)
                return
        self._call_for_owner(owner, meth, args, origin, context)
        return

    meth(*args)
